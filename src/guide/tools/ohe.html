LogicDWG Tools Guide / Yard Tool
Yard Tool

OHE

VIDDGPSTOOHE
vidDgpsToOhe.lsp

What it does

Reads OHE-type points from a DGPS CSV and draws a small 0.3 square beside the nearest track plus a stacked-fraction label, for each mast / portal.

Setup

  • CSV columns required: Code, Northing, Easting. The header can be anywhere near the top (title and blank lines above it are ignored). Alternative header names are accepted: Code / Point Code / Feature Code, Northing / North / N / Y, Easting / East / E / X.
  • Codes must start with OHE, OH, OM or PORTAL. The rest of the code is the identifier, e.g. OH 40/22A. Separators - . and space are converted to /.
  • Track polylines must exist on layer 1-track (draw them with Rail Track Generate first).

How to use

  1. Click Ohe > Generate (or type VIDDGPSTOOHE) and select the CSV.
  2. At the prompt Track polylines [Auto/Select] <Auto> press Enter to use every polyline on 1-track, or type S and select them.
  3. The tool finds the nearest track for each point and builds the square on the side away from the track (left-hand point = left, right-hand = right).
  4. A stacked MTEXT label (e.g. 40 over 22A) is placed on the rectangle edge, rotated to the track direction and kept readable.
  5. Everything goes on layer 1-OHE-CSV. The report lists valid rows, rectangles, texts and failures.

Notes

  • Square size 0.3 and text height 1.5 are set at the top of the LSP if you want to change them.

Pros & Cons

Pros

  • Very tolerant CSV reading - header anywhere, several aliases, any common delimiter.
  • Side-aware placement keeps every mast symbol clear of the track.
  • Handles OHE / OH / OM / PORTAL code families in one pass.

Cons

  • Needs the tracks drawn on layer 1-track first (or use Select at the prompt).
  • Only OHE-family codes are used - other rows in the CSV are ignored.
  • Symbol and text sizes are hard-coded at the top of the LSP.
